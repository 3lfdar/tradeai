# هیروی فریم‌به‌فریم

ویدیو به دنباله‌ی تصویر تبدیل شده و با اسکرول جلو و عقب می‌رود. تگ `<video>` در کار نیست.

مرورگر برای رفتن به هر نقطه از یک ویدیو باید تا نزدیک‌ترین کی‌فریم عقب برود و دوباره دیکود کند —
برای همین اسکراب کردن ویدیو می‌پرد. با تصویر جدا، هر فریم مستقل است و کشیدنش هزینه‌ای ندارد.

---

## نصب روی سایت

سه قدم:

**۱.** کل این پوشه را در سایتت کپی کن (مثلاً `/hero/`).

**۲.** در `<head>` صفحه:

```html
<link rel="stylesheet" href="/hero/hero.css">
```

**۳.** جایی که هیرو باید بیاید — معمولاً اولین چیز بعد از `<body>`:

```html
<div class="hero-track">
  <div class="hero-pin"><canvas></canvas></div>
</div>

<script src="/hero/hero.js"></script>
<script>
  heroScroll({ dir: '/hero/frames', dirMobile: '/hero/frames-mobile' });
</script>
```

همین. بقیه‌ی محتوای صفحه بعد از `.hero-track` می‌آید و وقتی ویدیو تمام شد، طبیعی ادامه پیدا می‌کند.

نمونه‌ی کامل و قابل اجرا: `index.html` در همین پوشه.

## تنظیمات

همه‌شان اختیاری‌اند؛ مقدارهای زیر پیش‌فرض‌اند.

| گزینه | پیش‌فرض | کارش |
|---|---|---|
| `dir` | `'frames'` | پوشه‌ی فریم‌های دسکتاپ |
| `dirMobile` | `'frames-mobile'` | پوشه‌ی نسخه‌ی سبک |
| `mobileBreakpoint` | `700` | زیر این عرض، نسخه‌ی سبک لود می‌شود |
| `count` | `479` | تعداد فریم‌ها |
| `smoothing` | `0.18` | هرچه کمتر، حرکت نرم‌تر و کمی کندتر |
| `background` | `'#000'` | رنگ پشت کادر |
| `eager` | `24` | چند فریم قبل از نمایش لود شود |

**سرعت اسکرول** با `count` تنظیم نمی‌شود، با ارتفاع `.hero-track` در `hero.css` تنظیم می‌شود.
الان `620vh` است. بلندترش کنی حرکت کندتر و سینمایی‌تر می‌شود، کوتاه‌ترش کنی سریع‌تر رد می‌شود.

## ساختن فریم از ویدیوی جدید

```bash
./build-frames.sh video.mp4
```

هر دو نسخه (دسکتاپ و موبایل) را می‌سازد. بعدش عدد `count` را در فراخوانی `heroScroll` به‌روز کن.

اگر ویدیوی جدیدت واترمارک ندارد، متغیر `DELOGO` را در `build-frames.sh` خالی بگذار.
مختصات فعلی برای واترمارک گوشه‌ی پایین-راست در کادر ۷۲۰×۱۲۸۰ تنظیم شده.

## چیزهایی که موقع ساخت به آن‌ها خوردیم

**ویدیوی اصلی در مرورگر پخش نمی‌شد.** کدکش `HEVC` بود که کروم و فایرفاکس پشتیبانی نمی‌کنند.
حالا که فریم است، این مشکل کلاً منتفی است — WebP همه‌جا کار می‌کند.

**کل کادر باید دیده شود.** ویدیو عمودی است؛ اگر با عرض صفحه پرش کنی، روی دسکتاپ ارتفاعش
سه برابر پنجره می‌شود و نصفش بیرون می‌ماند. برای همین با ارتفاع جا داده می‌شود و دو طرفش
مشکی می‌ماند — که چون پس‌زمینه‌ی خود ویدیو هم مشکی است، دیده نمی‌شود.

**امتداد دادن پیکسل‌های لبه جواب نداد.** برای محو کردن کامل مرز، لبه‌ی فریم را به کناره‌ها
کشیدیم؛ نویز سطرها تبدیل به نوارهای افقی درشت شد. مشکیِ خالص از تیره‌ترین لبه‌ی ویدیو هم
تیره‌تر است و مرز روشن نمی‌اندازد.

**۲۴ فریم واقعی، ۴۷۹ فریم نمایش.** ویدیوی اصلی ۲۴fps بود یعنی ۲۴۱ فریم. با درون‌یابی حرکت
دو برابر شد. روی این تصویر چرخشی تمیز درآمد ولی نصف فریم‌ها ساختگی‌اند.

**روانی حرکت از تعداد فریم نمی‌آید.** از `smoothing` می‌آید — فریم نمایشی نرم دنبال فریم
هدف می‌رود به‌جای اینکه بپرد. با ۲۴۰ فریم هم حرکت روان است.

## حجم

| | فریم | حجم |
|---|---|---|
| دسکتاپ (۶۶۰ پیکسل) | ۴۷۹ | ~۱۰ مگابایت |
| موبایل (۳۸۰ پیکسل) | ۴۷۹ | ~۵ مگابایت |

فریم‌ها تدریجی لود می‌شوند: ۲۴ تای اول قبل از نمایش، بقیه در پس‌زمینه. اگر کاربر زودتر
اسکرول کند، نزدیک‌ترین فریمِ موجود کشیده می‌شود تا صفحه سیاه نماند.

روی سرور مطمئن شو `Cache-Control` طولانی روی پوشه‌ی فریم‌ها ست شده — این فایل‌ها هیچ‌وقت
عوض نمی‌شوند و باید فقط یک بار دانلود شوند.
